移动端一键登录是怎么实现的?

TL;DR:一键登录(本机号码认证)的本质是借蜂窝数据通道让运营商网关直接认出 SIM 卡对应的手机号——App 拿临时 token,业务服务器用 token 换明文号码,全程用户不输入、不读短信、不输密码。

*(恢复自 2026-08-03 问答,原理与时序骨架忠实,细节 AI 重构。)*

为什么能「一键」

手机插着 SIM 卡走蜂窝网络时,所有流量都经过运营商网关,而运营商天然知道这张 SIM 卡对应的手机号(MSISDN)。一键登录做的事:让 App 走一条只有运营商能识别的蜂窝数据链路去「取号」——网关看到这条请求来自哪张卡,号码就是谁的。

完整时序(五方)

手机(App) → SDK → 运营商网关 → 业务服务器 → 运营商认证服务器
  1. App 内置运营商一键登录 SDK,发起取号(此时必须走蜂窝数据,Wi-Fi 下会先切蜂窝或要求开启)。
  2. SDK 经运营商网关的专用通道拿到一个临时 token(号码没有出运营商)。
  3. App 把 token 交给自己的业务服务器。
  4. 业务服务器拿 token + 自己的密钥调运营商认证服务器的 API,换回明文手机号。
  5. 业务服务器按手机号完成注册/登录,下发会话。

全程:用户只点一次「确认授权」;明文号码只在「运营商认证服务器 → 业务服务器」这一跳出现;短信验证码整条链路被绕过。

与短信验证码的对比

短信码是「证明你拥有这个号码」(读短信),一键登录是「运营商直接告诉你这是谁」(通道认证)。前者依赖短信可达性与用户输入,后者依赖蜂窝网络与 SDK 集成(三大运营商各自的 SDK,或聚合服务)。安全边界也变了个位置:从「短信不被劫持」变成「token 不被重放」——所以 token 短时效、一次性,且换号必须走业务服务器密钥。
