设计树写进提示词,AI 才会按设计树思考么?

TL;DR:是——skill 没有隐藏机制,SKILL.md 全文注入当轮上下文,行为逐字来自明文;但文本给的是协议,不是能力:按依赖拆解、权衡是模型既有习惯,skill 把隐性习惯固化成显式纪律,并反转默认倾向(默认自己消化决策、少打扰 → 摆上台面、问到底)。不给骨架时,AI 按问题类型选默认形状(查证先行/假设-验证/拆解-权衡)。骨架的价值不在咒语,在改变信息流——逼出什么、按什么顺序、谁查谁;「think step by step」一类咒语是空操作,对抗验证、鉴别诊断一类结构才高杠杆。

机制:skill 是纯文本,没有隐藏开关

以 grilling skill 为例(/grill-me 只是转发壳,真身是它):触发后 SKILL.md 全文注入当轮上下文,与普通指令地位相同。「设计树(design tree)」「前沿(frontier)」「按轮次问」「Q1 / ➡️ 推荐答案」的排版——全部是那几百字明文规定的。不执行时没有任何「设计树模式」在后台运行。

判据:把 SKILL.md 里的「design tree」换成别的词(如「决策 DAG」),思考的组织方式会跟着变——结构来自文本措辞,不是某个内置开关。

协议与能力之别

文本给的不是能力,是协议:

  • 激活并固化:把问题拆成有依赖关系的子决策、按依赖序提问,模型本来就会;skill 把它收拢成确定性流程(轮次制、frontier 重算、答完才下一轮)。
  • 规定格式:❓/➡️/--- 的排版完全来自模板。
  • 反转默认倾向:默认纪律是「例行判断自己做、实质分歧才问」(少打扰);skill 明文覆盖它,变成「relentlessly 问到底、nothing left silently assumed」。

准确的说法:skill = 把模型既有能力包装成可复用、可触发、格式确定的 SOP。对应 atlas 固化光谱(路标→规则→公路→隧道),这正是一级「公路」。

默认思考形状(不给骨架时)

没有内置的单一「思考流程」;推理轨迹的形状主要由问题类型塑造:

问题类型默认骨架
事实型(为什么报错)查证先行:先读代码/跑命令,拿到事实再推理
调试假设-验证循环:列候选根因 → 找判别性证据 → 收窄 → 修复/回归
设计/方案拆解 → 列选项 → 权衡 trade-off → 带理由推荐
需求模糊例行歧义自己消化并在交付里标注假设,实质歧义才问(默认少打扰)

两个底层事实:

  • 思考是当轮生成的,不是跨轮草稿纸;每轮带着上下文重建,没有「昨天想到一半」可言。持久化靠外置:memory、CLAUDE.md、文档——外置文件才是 AI 的长期思考。
  • 单轨迹采样:「权衡过 A/B/C」是轨迹里写出来的比较,不是后台真跑了三个平行实例;真并行要物理化成多 agent(各持隔离上下文 + 交叉评审)。

设计树没有赋予「会拆解」这个能力,它改变的是三点:禁止沉默假设(不许私下替用户决定)、反转交互协议(我一次给结论 → 分轮等你)、拆解结构可核查(临时不成文 → 持续存在,漏了哪看得见)。

推理骨架目录(六阶段)

本目录由当日两轮问答合并重构(AI 重构):第一轮 A-F 主目录,第二轮补遗;⭐ 为补遗中标「杠杆更高」的条目。骨架分「内心版」(一条轨迹里自己过一遍,便宜但会漏)与「物理版」(多 agent 隔离执行+交叉评审,贵但真独立);下表触发语两版通用。

A. 定义:把问题本身想清楚

骨架核心动作触发语
Five Whys对「为什么」连问到根因,不在症状处停「连问 why 直到根因」
Inversion 反向问「怎么保证搞砸」,再逐条反着防「先反过来想:这项目怎么死」
Pre-mortem 事前验尸假装「三个月后已失败」,从失败往回推原因清单「假设它失败了,写验尸报告」
问题分诊(Cynefin 式)先分类例行/复杂/混沌/未知,混沌类先止血再分析「先判断这属于哪类问题」
⭐ 终态先行(working backward)终态产物(发布公告/最终文档/完成画面)先写出来,从终态倒推现在干嘛「先把终态产物写出来」
⭐ 最高风险假设先行列出计划成立的全部前提,按 不确定性×杀伤力 排序,用最便宜的实验先测最吓人的「列出全部前提,标出最不可靠的,先测它」

B. 发散

骨架核心动作触发语
⭐ 先例检索生成前先问「谁在别的领域解决过最近似的问题」——多数新问题是旧问题的变体;不问,AI 会闷头原创「先找最接近的已解问题再设计」
评审团(judge panel)不同立场(MVP 优先/风险优先/用户优先)独立出 N 个方案再互评打分「给我 3 个立场不同的独立方案,再互评」
Fermi 估算拆成可估的乘积项,先定量级再谈细节「先做数量级估算」
多路扫描按 N 个互盲角度各搜一遍(按名/按内容/按时间)「换 3 个互不相关角度各找一遍」

C. 收敛

骨架核心动作触发语
决策矩阵选项×标准×权重逐格打分,把「我觉得 A 好」翻译成可核对的表「列个加权决策矩阵」
可逆性分级(Type 1/2)可逆的立刻做,只有不可逆的才配深入论证「这决定可逆吗?可逆就直接做」
外部视角先问「这类事的一般基率是多少」,再调到具体案例,防「这次不一样」「先给基率,再谈例外」
显式置信度结论必须带置信度,不许裸断言「所有结论标置信度」
⭐ 止损标准预写「到 X 时点,若 Y 还没发生就砍」;没有它的项目会变僵尸「写清什么信号出现就放弃」

D. 检验(杠杆最高的一组)

骨架核心动作触发语
⭐ 对抗验证单派一个「职业反驳者」专门否证结论,拿不准默认驳倒;生成者与反驳者分离,防自己夸自己「专门反驳你自己刚才的结论」
⭐ Chesterton's Fence动「看着怪/多余」的代码前,先找出它当初为何存在;找不到理由没资格删——AI 改代码的头号事故来源「先讲清这段怪代码在防什么」
⭐ 桌面推演(desk check)动手前把执行过程纸面单步走一遍,每步问「此刻状态是什么、下一步读什么」;成本近零抓错率高「先单步推演一遍再写」
可证伪性检验问「什么证据出现我就该改主意」,并把判别性实验写出来「什么事实能推翻它?」
Steelman 双方把反对观点写到对方辩手都挑不出毛病,再反驳「先最强的形式重述反方」
独立复算不看前答再算一遍;两次不一致=有坑「别看刚才的,独立再算一次」

E. 外化成工件

骨架核心动作触发语
⭐ 不变量先行先写「无论代码怎么跑、任何时候都必须成立」的性质清单;此后审查=查这次改动碰没碰不变量「先列不变量再动手」
ADR每个架构决定写:背景/决定/后果/被否掉的备选——不写备选不算想清楚「给这个决定写 ADR」
Test-first测试是把推理变成可执行物的过程;写不出测试=还没想清行为「先写失败测试再实现」
接口先行先写 API 签名/文档/使用示例,代码后行「先只写接口和使用示例」
Walking skeleton最细的一条端到端贯穿线先跑通,再长肉「先走通最薄的全链路」

F. 调试

骨架核心动作触发语
⭐ 鉴别诊断(医学式)列假设清单,给每个假设找判别性证据(能区分假设的,而非支持它的),逐个排除「列鉴别诊断表」
二分在变更空间里二分:git bisect、最小复现、注释一半代码「最小复现先做出来」
最小差异找「能跑的案例」和「坏案例」间最小差异,答案往往在差异里「对比能跑和不能跑的差在哪」
先测量再优化性能问题禁止拍脑袋猜热点,先 profile「先 profile 再动手」

小件(一句话版)

effort×impact 四象限(排优先级)/ TOC 瓶颈优先(只优化瓶颈,其余优化是错觉)/ 两步改动法(先提交「让改动变容易」的重构,再做变简单了的那步)/ 状态机先行(交互先枚举全部状态+转移,把不可能状态从表示上消灭)/ 触发-行动表(计划全写成「若 X 则 Y」,执行率完全不同)/ BLUF 结论先行(先结论+置信度再展开)/ 失败台账→清单(同类 bug 第二次出现就升级成 checklist 入规则文件)。

三条校准

  1. 咒语无效,结构有效。「think step by step」「take a deep breath」「进入专家模式」对当前模型是空操作——能力本来在,念咒不改变信息流。有效的是五种改变信息流的手段:强制外化(写出工件)、规定顺序(事实先于判断、发散先于收敛)、分离角色(生成者与反驳者分开)、显式化(概率/权重/假设落纸面)、加对抗环节。
  2. 内心版与物理版是两种东西。内心版(一条轨迹里自己列举权衡)便宜但会漏;物理版(多 agent 隔离上下文+交叉评审)贵但真独立。workflow 编排里的 adversarial verify / judge panel / loop-until-dry / completeness critic 就是本目录诸骨架的物理实现——概念同源。
  3. 组合强于单用。实战组合拳:Pre-mortem(找死法)→ 设计树(把死法变成待决策分支)→ 对抗验证(逐条反驳结论)→ ADR(钉档)——正好覆盖定义/展开/检验/存档。

两条 meta(比任何单条骨架都值钱)

  • 要实验,不要论证:与 AI 协作最大的单点杠杆——遇到分歧或不确定,别让 AI「再多分析分析」(分析只会越叠越厚、越说越自信),让 AI 设计最便宜的判别性实验,一刀见血。
  • 重复失败 → 结构成:同类问题第三次出现就别再修了,改结构——清单、类型约束、工具化、流程卡点。前两次是运气,第三次是系统性缺口。
