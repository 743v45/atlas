# 「读过模板=会生产运维」:纸面样板冒充经验

> **TL;DR**:错在把「配置齐全」读成「跑得起来」——全套 K8s/Helm/Prometheus 从未执行过一次,完整性与真实性是两回事。

- **状态**:fixed(已修正)
- **日期**:2026-08-07
- **出处**:全栈/全运维学习路线的 subagent 项目审查,xiaopacai 项目被揭穿

## 经过

需求原话:「当我想学全栈,全运维,我要学什么……分析一份报告」。subagent 审查报告揭穿 xiaopacai「看起来完整、实际从未跑过」:全套 K8s/Helm/Prometheus 配置齐全但从未执行;三套互相矛盾的 CD 管线并存(SSH+PM2 / Helm+ghcr.io / 两者混用);占位 URL 全是 `*.example.com`;未执行过的 typo 遍地(`wc -h << EOF`、`frozen-locklockfile`);PM2 与 k8s 两套运行时并存。报告结论「双峰分布极其明显」,这一极是「最危险的」。

## 根因

「读过模板 = 会生产运维」的幻觉:模板看得多、结构都认识,就把结构完整性当成了运行真实性。矛盾信号(三套 CD 并存、两套运行时并存)本是「没跑过」的铁证——跑过任何一套,另一套的矛盾就会暴露——但读模板的方式永远不会触发它们。

## 修正

学习路线阶段 3 专破:亲手跑通一次真部署——让「读过」变成「跑过一次」。可复用判据:运维类产物的合格线不是「文件齐全」而是「执行过一次」;见到多套互斥方案并存、占位符未替换,直接判「从未跑过」。
