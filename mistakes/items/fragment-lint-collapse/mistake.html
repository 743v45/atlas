28 个分片各过 gate,合并后 lint 溃败

TL;DR:错在把 task 级 gate 当成了全局 gate——分片各自达标,拼起来溃败;全局质量门禁必须独立于分发单元存在。
  • 状态:fixed(已修正)
  • 日期:2026-07-28
  • 出处:robin CLI 会话,28 个 agent 分片并行开发

经过

28 个 agent 并行开发,各自通过 task 级 gate 交付(单片 lint/build/test 达标)。合并后用户一句话定案:「lint 全是问题。修复」——整体仓的 lint 溃败,task gate 一个都没拦住。

根因

我以为是某几个 agent 质量差,其实是门禁架构缺口:task gate 验证的是「这个分片在它的上下文里合格」,管不到「28 份改动叠在同一份全仓配置下」——分片边界不是质量边界,风格/依赖/unused 的冲突恰恰发生在边界上。没有独立的全局 gate,整体质量就处于无人值守状态。

修正

独立全局 gate:分片全部合并后,全仓级 lint/build/test 单独跑一遍、不过不算完。可复用判据:凡并发分片开发,门禁至少两层——task gate(分发单元)+ 全局 gate(合并整体);后者不可被前者代言。
