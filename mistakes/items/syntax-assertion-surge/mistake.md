# 「语法对」被打脸:文档确认前不断言

> **TL;DR**:错在把「看起来像」当「确认过」——对可查证事实凭印象说「对」,用户拿报错回来时,信任已经赔进去了。

- **状态**:fixed(已修正)
- **日期**:2026-08-05
- **出处**:Surge ssh 代理行配置,本机会话

## 经过

用户配置 Surge 代理(内网 IP 已脱敏):`JumpServer = ssh, 10.x.x.x, 22, username=root, private-key-path=~/.ssh/id_rsa`,载入失败 `Invalid line #20`。AI 此前对这行断言「语法对」。用户贴出报错后,认错原话:「报错说明 Surge 不认这行的语法——我上一条说"语法对"是错的,这次我查官方文档确认准确写法,不猜了。」此后搜索配额耗尽、文档站被网络策略挡,仍换读取通道把官方文档读到才给写法。

## 根因

我以为是记忆里「ssh 行大致长这样」足够用,其实是把印象当成了断言资格:语法、接口签名、配置格式这类**可查证事实**,「像」和「对」之间的差距只能靠文档弥合——凭印象说「对」是负资产:错得越自信,用户越会把报错归因到别处,排障越绕路。

## 修正

文档确认前不断言:对可查证事实,要么查文档再答,要么明说「未查证,以下是印象」。查证遇阻(配额/网络)换通道也要查到——这次换了读取工具才读到官方文档。可复用判据:凡是能一句「等等,我查一下」解决的问题,就不该用一句自信的「对的」去赌。
