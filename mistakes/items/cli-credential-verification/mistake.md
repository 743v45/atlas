# 「你不验证一下吗」:凭据采集无验证闭环

> **TL;DR**:错在把「采集」当成了「登录」——粘什么存什么,垃圾凭据也绿灯,故障推迟到下一个命令才爆。

- **状态**:fixed(已修正)
- **日期**:2026-07-28
- **出处**:内部 DNS 服务 CLI(robin-cli)login 命令,双层鉴权(网关 cookie + Basic)

## 经过

CLI `login` 只提示「从浏览器 DevTools 复制网关 cookie 值并粘贴」,随手粘 `123` 也直接「已保存网关 cookie」。用户当场揭穿:「你不验证一下吗。我随便填写的。账号密码。密码隐藏的方式输入吧。输入账号的时候，密码就得传入，隐藏的。并且要验证密码」。

## 根因

我以为是流程步骤(采 → 存 → 用时再说),其实是把「采集到字符串」当成了「登录成功」:无验证的保存让坏凭据拿到绿灯,故障不消失只是推迟——推迟到下一条命令、离根因更远处爆,排障成本翻倍。同时密码明文回显,把安全也押在了「用户不会犯错」上。

## 修正

login 重构为闭环:采集(账号明文 + 密码隐藏输入 + cookie 粘贴)→ 立即打真实接口验证(GET /api/domains,双层鉴权 Basic + 网关 cookie,200 才保存)→ 失败提示哪层失败并不落盘。可复用判据:凭据类输入,保存前必过一次真实验证;验证还要能区分失败层(网关 vs 账号),给用户可行动的报错。
