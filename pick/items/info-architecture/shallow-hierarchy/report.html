浅三层 + 宽表

TL;DR：被 pick 实际采用的方案：域→类别→条目浅三层，类别内用宽表做属性对比——层级税最低、每层回答一个独立问题，74 条目仍一屏一族。
  • 结论：adopt（推荐——本库生产验证）
  • 核实日期：2026-08-27（74 条目实测）

基本信息

项值来源
形态方案：域(5) → 类别(10) → 条目(74)，索引页只列域[2]
层级税每层一跳 + 一类校验规则（门禁：类别必须归属域、条目未入树告警）[2]
实测74 条目顶层页高约一屏（~1000px）；域页过滤/排序精确[2]

为什么选

  • 每层一个独立问题：域答「这是哪族问题」，类别答「族内按什么维度对比」，条目答「这个东西怎么样」——没有一层可被合并 [2]。
  • 宽表吃掉对比需求：类别内的属性对比由宽表 + 决策矩阵承担，不需要更深的子层——这是「层级浅而不失分辨力」的关键 [2]。
  • 层级税最低：从索引到任意报告 3 跳；膨胀时横向拆类别（并系拆分）而非加深 [2]。

对比

vs 深分类学树 / 扁平多面 / 网络图：见 ../comparison.md。

风险与注意

  • 域超过 7±2 个时顶层需再分组（加「界」）——当前 5 个，健康 [2]。
  • 宽表依赖 matrix 纪律：类别 columns 与条目 matrix 对齐靠 build 门禁维持。
