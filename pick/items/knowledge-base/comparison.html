个人知识库横评（AI 共建视角）

调研时间 2026-08-27，方法 gh（GitHub CLI 一手数据）+ tvly（Tavily）。 核心命题：AI 共建知识库的本质是「AI 对存储层的原生访问权」——agent 能不能不经过 API / 中间商，直接读写你的知识资产？2026 年最大动态是全行业向这个方向收敛：Obsidian 官方发布 CLI 与 agent skills（⭐47k）、思源内置 MCP 与智能体、Bear 2.8 带 CLI+MCP——「notes as agent context」成了新轴线（Ry Walker Research 2026）。

一、判断框架：三个问题定生死

  1. 数据在哪——纯 Markdown 文件（可 grep / diff / 直写）还是应用自管数据库（API 代理）？
  2. AI 怎么写——文件系统原生访问，还是 API / MCP 通道（有速率、有 schema、有中间层）？
  3. 换掉它多贵——阅读器层可换（数据零迁移）还是存储层锁定（导出有损）？

本选型的答案：数据必须是纯 md（1），AI 必须文件直写（2），存储层永不锁定（3）——Obsidian 只承担阅读器角色（3 的保险）。
