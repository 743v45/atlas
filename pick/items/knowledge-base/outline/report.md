## 生命周期 · 第一幕：选型（2026-07-29/30）

三条件：「最火的开源文档服务 + 方便 AI 接入 + 页面好看」[3]。选型对话中的两个关键澄清：

- **一次性文档 ≠ 平台选型**：先辨明「做一篇文档」和「选一个文档平台」是两件事；结合已有 Hugo 博客，确立分工——**Hugo =「思考」**（对外发布的观点长文），**文档库 =「知识」**（半结构化、持续攒、给自己和 agent 查）[3]。
- **决定性一句**：「ai 写读内容，但是展示要好看。我要看的。」——AI 是生产者/操作者（要有 API），展示层是给人看的漂亮阅读页。两条并集直接锁定 Outline [3]。

### 对比矩阵（选型时刻）

|---|---|---|---|

| Dify | AI 应用平台（LLMOps），文档是喂进去的语料 | 谷歌推荐，但「不在里面写文档」、无给人看的阅读页 | 错位落选 [3] |

| Obsidian | 本地笔记 | 无 web 服务、无现成 API 给 agent 查 | **pass** [3] |
| AFFiNE | 颜值更高 | 自托管是微服务地狱、AI 绑云账号 | **pass** [3] |

## 生命周期 · 第二幕：部署（2026-07-30）

- 形态：本机 Docker，3 容器（outline + postgres + redis）；v1.9.1 起 `FILE_STORAGE=local` 默认本地磁盘存附件，**免 MinIO**，compose 显著简化 [3]。
- **坑一（认证）**：自托管**不自带本地密码登录**，必须挂第三方登录（当时选 Google OAuth）；redirect URI 从源码坐实为 `/auth/google.callback`（`google.ts:51`）[3]。
- **坑二（macOS keychain）**：`docker compose pull` 拉公开镜像也机械地先读 osxkeychain，非交互会话读不到就整体挂掉——解锁钥匙串或去掉 credential helper [4]。
- 自托管共踩 **9 坑**，详单存小天机会话 53f490e3（本节仅概述两处关键坑并指向，不复制）[5]。

## 生命周期 · 第三幕：使用（2026-08）

- 按 IA 方法论组织内容，建立写入流水线（agent 经 API/插件直写文档）[3][7]。
- 两个 collection 并行服务不同场景，其一为「技术设计」（团队选型沉淀，如自动化开发平台 10+1 份定位报告）[3][6]。

## 生命周期 · 第四幕：弃用（2026-08-23/25）

- **弃用主因**：排版硬伤 + 无 `[[` 式双链（只有文档间普通跳转，反链/图谱缺失）——核心需求补不上；AI 批量读写走 API 慢；数据在 Postgres/对象存储而非本地文件系统，agent 操作受限 [7]。
- 数据去向（两路）：2026-08-23 「技术设计」collection 经 lark-cli 迁飞书（会话 0e78d1c6）[6]；2026-08-25 整体废弃，个人知识 105 篇迁本地 Markdown 库 taevasidian（会话 be457b46）[7]。

## 教学价值（unique）

选型看生命周期，不看当下：第一幕的对比矩阵里 Outline 是无可争议的胜者——三条件全 ✅；但决定去留的是第四幕的「排版硬伤 + 双链缺失 + 数据不本地」，这些在选型矩阵里一列都不是。**选型时刻的最优解 ≠ 生命周期的最优解**：对比矩阵回答「现在谁最好」，只有把部署成本、使用摩擦、退出成本放进同一张表，才是完整的选型。这正是本条目以 hold（而非删除）留档的原因。

## 风险与注意

- BSL 1.1 非标准开源：自托管免费但有用途条款限制 [1]。
- 已从个人工作流移除；团队协作 / 权限 / 结构化知识库场景仍是合格选项（2026 年仍是自托管团队 Wiki 头部开源选择之一，与 Docmost 等并列，Elestio 2026 对比文）[8]。
- 9 坑详单在小天机（跨机不可直查），引用需注意会话存档位置 [5]。
