# 字符表现形式

> **TL;DR**:混排对齐只需记四类——数字右对齐(网页开 tabular-nums)、中文左对齐天然等宽、英文左对齐、Emoji 独占一列;完整图谱 16 类,差异全部挂在宽度、呈现、方向、可见性四条轴上。

- **结论**:adopt(作为混排排版的默认参考)
- **核实日期**:2026-08-27
- **本文双层**:第 1 层常用速查(日常排版够用)/ 第 2 层全量图谱(16 类,按需深入)

## 基本信息

| 项 | 值 | 来源 |

一个前提贯穿全文:**表现形式 = 码位 × 字体 × 渲染环境**。同一码位在不同终端/浏览器/字体里呈现不同;文中凡是"看不到演示效果"的地方,本身就是这条前提的证据。

## 第 1 层 · 常用速查(四类)

### 1.1 四类核心矩阵

| 维度 | 数字 | 英文 | 中文 | Emoji |
|---|---|---|---|---|
| 天然宽度 | 1 格(全角变体 2 格) | 1 格,字母宽窄不一 | 恒定 2 格 | 名义 2 格,实际 1~2 格不定 |
| 等宽性 | 可切换(比例/等宽) | 比例字体不等宽 | 天然等宽 | 无 |
| 对齐建议 | 右对齐(对齐小数点) | 左对齐 | 左对齐 | 独占一列居中 |
| 宽度属性(EAW) | Na / F(全角变体) | Na | W | W 或 A(歧义) |
| 字体归属 | 常被 CJK 字体接管 | 西文字体 | CJK 字体 | 独立彩色字体 |
| 跨平台一致性 | 高 | 高 | 中(字形微差) | 最差(各平台各画) |
| 基线 | 与文字齐 | 与文字齐 | 与文字齐 | 漂移,大小不一 |
| 典型陷阱 | 比例数字错位、全角数字 | 右对齐参差 | 标点全半角混用 | 宽度不定致错位 |

宽度分类依据 UAX #11 的 East Asian Width 属性 [1];Emoji 的呈现(黑白/彩色)与宽度受变体选择器影响,规范见 UTS #51 [2]。

### 1.2 对齐演示

数字的本质是**对齐小数点,不是末字符**:

```
右对齐(整齐)             左对齐(乱)
   9.50 元                9.50 元
1234.00 元                1234.00 元
 312.75 元                312.75 元
```

终端默认等宽所以总是齐;网页默认比例字体,`1111` 比 `8888` 窄,不开 tabular-nums 就错位。

中文标点全半角:

```
全角:今天,天气很好——《春》……
半角:Today, it's fine--"Spring"...
错误混排:今天,天气很好!(半角逗号 + 全角叹号,最常见事故)
```

Emoji 宽度不定,现场演示——若你终端把 ✅ 算 2 格、⚠️ 算 1 格,竖线就不齐,这不是笔误,是问题本身:

```
名称  | 数量
------+------
✅    | 12
⚠️    | 345
ℹ️    | 6789
```

### 1.3 混排速查规则

```
数字   → 右对齐;网页加 font-variant-numeric: tabular-nums
中文   → 左对齐(天然等宽);正文标点必须全角
英文   → 左对齐;右对齐必乱
Emoji  → 独占一列、居中,永远不与文字/数字同格
中英混排 → 词间加空格(盘古之白):使用 Claude Code 写代码
①②③ 带圈序号 → 占全角,按 2 格计宽
⚠️☑️ 歧义字符 → 表格中视为不可靠宽度,别承担对齐职责
全角数字/全角字母 → 输入法事故,出现即修
```

## 第 2 层 · 全量图谱(16 类)

### 可见阵营(1–12)

#### 1. 数字:8 种形式

| 形式 | 示例 | 说明 |
|---|---|---|
| 半角阿拉伯 | `0123456789` | 默认,1 格 |
| 全角数字 | `０１２３４５６７８９` | 输入法全角模式误开,2 格,视为事故 |
| 比例数字 | 1111 0000 | 1 窄 0 宽,网页默认 |
| 等宽数字 | 1111 0000 | 同宽,表格对齐必备(CSS `tabular-nums`) |
| 中文数字 | 一百二十三 / 壹佰贰拾叁 | 大写用于财务防篡改 |
| 罗马数字 | Ⅰ Ⅱ Ⅲ Ⅳ | 独立码位,偏全角 |
| 千分位 | 1,234,567 / 1.234.567 / 1 234 567 | 中英美 / 德 / 法三种流派 |
| 上下标 | x² H₂O m³ | 独立码位,不靠排版功能 |

#### 2. 英文:7 种形式

大写 `ABC` / 小写 `abc`;等宽(代码)`if (x)` vs 比例(正文);Kerning 紧排(`AVA` 里 A、V 咬合,等宽终端下不可见);连字 `ﬁ ﬄ` 与编程字体连字(`=>` `!==` 合形,依赖字体);小型大写 `ꜱᴍᴀʟʟ ᴄᴀᴘꜱ`(正规做法是 OpenType 功能,Unicode 硬拼是替代);斜体 *italic*(真斜体字形,西文专属)。

关键:字母宽度天然不一 → **英文列永远左对齐**。

#### 3. 中文:7 种形式

简体/繁体(汉字排版 / 漢字排版);全角标点 `,。、;:?!《》——……`(各占 1 汉字位)vs 半角 `, . ; : ? ! -- ...`;全角字母数字 `Ａｂｃ１２３`(事故);直角引号 `「」『』`(繁体/日文传统)vs 弯引号 `"" ''`(简体规范,CJK 字体里渲染为全角宽);"斜体"不存在——汉字没有斜体字形,机械倾斜不被认可,中文强调用粗体或着重号(字下加点)。

核心优势:**天然等宽**,纯中文列怎么排都齐;坑在标点全半角混用与中英混排空格(盘古之白)。

#### 4. Emoji:7 种形式

| 形式 | 示例 | 说明 |
|---|---|---|
| 彩色图形 | 😀 🚀 🍎 | 默认 emoji 呈现 |
| 文本形式(黑白) | ❤︎ ☀︎ ☑︎ | 同码点 + VS15(U+FE0E) |
| 强制彩色 | ❤️ ☀️ ☑️ | + VS16(U+FE0F),与上一行同字符不同呈现 [2] |
| ZWJ 组合 | 👨‍💻 👨‍👩‍👧‍👦 | 零宽连接符拼接,老系统散架 |
| 肤色修饰 | 👋🏻 👋🏽 👋🏿 | 修饰符跟缀 |
| 旗帜 | 🇨🇳 🇯🇵 🇺🇸 | 区域指示字母拼成,多数终端显示为字母 CN/US |
| 键帽 | 1️⃣ 🔟 | 数字/井号 + 组合框 |

三个坑:宽度不定(终端按 1 或 2 格各算各的);基线漂移(与文字不在一条基线);跨平台长得不同(同一 🙂 各厂各画,个别还有语义偏差)。

#### 5. 标点:同一功能 N 个码位

破折号四兄弟:`-` hyphen(半角)、`–` en dash(范围 3–5 页)、`—` em dash(全角)、`―` horizontal bar(全角)。中文破折号是**两个** em `——`,省略号是两个 U+2026 `……` ≠ `...`。引号四流派:直 `" '`、弯 `"" ''`、直角 `「」『』`、CJK 字体态全角弯引号。

#### 6. 数学符号

运算 `≠ ≤ ≥ ≈ ± × ÷ √ ∞ ∑ ∫ π`;**负号陷阱** `−`(U+2212)≠ `-`(U+002D),论文复制进代码直接语法错误;**数学字母**约 20 种皮肤 `𝐀` 粗体、`𝐴` 斜体、`𝒜` 花体、`𝔄` 哥特、`𝔸` 双线——独立码位、屏幕阅读器读不出、搜索不到,装饰性使用一律拒绝;上标下标 `⁰¹² ₀₁₂`、存量分数 `½ ¾`。

#### 7. 货币与单位

`$ € £ ¥ ₩ ₹ ₽ ¢` + 全角变体 `￥ ＄`;CJK 兼容区全角单位 `㎝ ㎞ ㎏ ㎡`(乱码感来源);`° ℃ ℉ % ‰`;双胞胎 `µ`(U+00B5 micro sign)≠ `μ`(U+03BC 希腊 mu)。

#### 8. 其他字母系统

希腊 `ΑΒγδΩ`、西里尔 `Абв`——**同形字陷阱**:`a о а ο ａ` 五个肉眼几乎一样,分属拉丁/西里尔/希腊/全角,钓鱼域名经典原料;谚文 `한` 预组合单码位 ≠ `한` 三 jamo 组合(显示同、长度异);假名 `あ`(平假名)、`ア`(片假名)、历史遗留**半角片假名** `ｶﾀｶﾅ`;注音 `ㄅㄆㄇㄈ`;变音字母 `é ñ ü`;天城体 `नमस्ते` 元音附标重排——**显示顺序 ≠ 码位顺序**。

#### 9. RTL:方向反转的文字

`العربية`(阿拉伯文)、`עברית`(希伯来文)整段从右往左;与 LTR 文字混排时由双向算法决定顺序 [3],同一句在不同渲染器里顺序可能不同——这是算法在工作,不是 bug。

#### 10. 黑白符号(emoji 的邻居)

几何 `■ □ ▲ ▼ ◆ ○ ● ◇`;星 `★ ☆ ✦`;箭头 `← → ↔ ⇒ ➜`(带 VS16 可变 emoji `➡️`);键盘 `⌘ ⌥ ⌃ ⇧ ⏎ ⎋ ⌫`;**带圈字符** `① ② ③`(全角,中文序号刚需)、`Ⓐ ⓐ`、`❶ ❷`、`㈠ ㊀`;杂项 `♠♥♦♣ ♀♂ ♈ ♻ ☀ © ® ™`。特点:单色、跟随文字色、宽度多为歧义(A)——黑白符号与 emoji 之间是光谱不是鸿沟 [1][2]。

#### 11. 制表符号:终端 UI 的骨架

`┌ ─ ┬ ┐ │ ├ ┼ ┤ └ ┴ ┘` 单线、`╔ ═ ╗` 双线;`tree`、`git log --graph`、htop 全靠它。等宽终端里"字符画表格"成立条件只有两个假设——汉字宽 2 格 + 数字右对齐:

```
┌──────────┬────────┐
│ 商品     │    价格│
├──────────┼────────┤
│ 苹果     │    9.50│
│ 巨峰葡萄 │  123.00│
└──────────┴────────┘
```

只在等宽终端成立,别贴进网页。

#### 12. 高位平面文字

盲文 `⠓⠑⠇⠇⠕`(8 点阵,天然等宽);埃及圣书体 `𓀀`、楔形文字 `𒀀`(码位在辅助平面 SMP,字体未覆盖即豆腐 `□`)——若你看到方块,又是"表现形式取决于字体覆盖"的证据。

### 不可见阵营(13–16)——排版炸弹

#### 13. 空白家族

| 字符 | 码位 | 宽度 |
|---|---|---|
| 普通空格 | U+0020 | 1 格 |
| 全角空格 | U+3000 | 1 汉字 |
| 不换行空格 nbsp | U+00A0 | 1 格,不折行 |
| en / em 空格 | U+2002 / U+2003 | 0.5 / 1 汉字 |
| 细空格 thin | U+2009 | 窄 |
| **零宽空格** | U+200B | **0 格,完全不可见** |

零宽空格最阴:看不见、量不出,复制粘贴随身携带,进 JSON/代码/文件名都是事故。

#### 14. 零宽控制符

ZWJ(U+200D)拼 emoji;ZWNJ(U+200C)**断开**连字——印地语、波斯语的语法正确性依赖它;软连字符(U+00AD)平时隐形,只在换行处现身为 `-`。

#### 15. 方向控制符

LRM(U+200E)/ RLM(U+200F)标记方向;RLO(U+202E)可把整段文字视觉反转——恶作剧与欺骗性文本常用原料 [3]。

#### 16. 组合字符与归一化

`é` 两种合法编码:`U+00E9` 整字符或 `e` + `U+0301` 组合符——显示相同、字节不同,**搜索匹配/去重失败的元凶**(NFC/NFD 归一化存在的原因);组合符可无限叠加 `é̈̂`,一个"字符"越叠越高。

### 四条差异轴(收束)

| 轴 | 属性 | 关键取值 | 出处 |
|---|---|---|---|
| 宽度 | East Asian Width | F / W(全角)、H / Na(半角)、**A(歧义,表格错位主犯)**、N(中性) | [1] |
| 呈现 | Emoji Presentation | text / emoji 默认 + VS15(U+FE0E)/ VS16(U+FE0F)切换 | [2] |
| 方向 | Bidi Class | L / R / AL / AN … | [3] |
| 可见性 | (非官方工程口径) | 零宽与否 | — |

## 落地:宽度计算与清洗

- **宽度计算**:Python `unicodedata.east_asian_width(ch)`(返回 F/W/H/Na/A/N)+ `wcwidth` 包(终端列宽);JS `string-width`(npm,表格库常用)、`emoji-regex`(emoji 序列切分)
- **数字对齐**:CSS `font-variant-numeric: tabular-nums` 一行解决网页数字列错位
- **归一化**:JS `'é'.normalize('NFC')`;Python `unicodedata.normalize('NFC', s)`——入库/检索/去重前先归一
- **入库清洗清单(事故码位)**:`U+200B` 零宽空格、`U+00AD` 软连字符、`U+200E/200F/202E` 方向控制、`U+3000` 全角空格、全角区 `U+FF01–FF5E`
- **注意**:ZWJ/VS16 是上下文相关的(U+200D 拼组合 emoji、U+FE0F 定彩色呈现),无脑全局删除会拆散 emoji——清洗按场景白名单化,不做一刀切

## 风险与注意

- 歧义宽度(A)字符由各渲染器自行解释,同一字符不同终端宽度不同 [1]——本文演示块若错位即是现场证据
- 零宽/方向控制符进入数据列即事故,入库前过滤
- 数学字母(𝐀)读不出、搜不到,拒绝装饰性使用
- SMP 字符(圣书体等)在未覆盖字体下为豆腐块,面向分发的文档慎用
- **待验证**:各终端对 ⚠️/ℹ️ 类歧义字符的具体宽度实现逐家不同,未逐一实测;需要时按 `echo -n '⚠️' | wcwidth` 类方法逐环境验证
