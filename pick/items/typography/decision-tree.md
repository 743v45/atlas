# 排版基础 · 选型设计树

> 根问题的决策路径。叶子格式 `- 叶：[名](slug/) verdict`，build 校验与 meta 一致（RULES.md 第 8 节）。

## 根问题

混排文本（中西文 + Emoji + 符号）做表格与排版时，字符的宽度、呈现、对齐行为有没有一份可查的完整图谱？（调研 2026-08-27，依据 UAX #11 / UTS #51 / UAX #9）

## 分叉与决策

### D1 常用版与全量版：拆两个条目还是一个条目内分层？

- **拆两个条目**：索引层即可区分,但全量版必然包含常用版全部内容 → 内容重叠、双头维护,违背 RULES 反双头原则。
- **单条目内分层**：一份 report.md,『常用速查』在前（四类核心矩阵 + 速查规则代码块,查表即走）,『全量图谱』在后（16 类 + 四条差异轴,按需深入）——单一事实源。
- 决策：单条目内分层（2026-08-27 与 owner 确认）。

### D2 分层机制要不要上升为通用规则？

- 选项：不进规则 / 轻量可选 / 强制。
- 知识型条目（查一个,非选一个）会持续出现,轻量建议性措辞（不强制、不影响工具选型类）成本最低、收益即时。
- 决策：轻量进规则 → RULES.md 第 3 节第 7 条「知识参考类条目建议双层」（2026-08-27 与 owner 确认）。

### D3 维度怎么组织才不散？

- 16 类字符若逐类自由描述会发散;差异收束到四条轴：宽度（EAW [1]）、呈现（Emoji Presentation + VS15/16 [2]）、方向（Bidi Class [3]）、可见性（零宽与否,工程口径）——前三条是 Unicode 官方属性。
- 决策：全量层逐类展开,收束节四轴总表;速查层只保留四类 × 8 维矩阵 + 8 条速查规则。
