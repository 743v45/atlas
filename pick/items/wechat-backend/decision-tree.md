# 微信小程序后端方案 · 选型设计树

> 叶子格式 `- 叶：[名](slug/) verdict`，build 校验与 meta 一致（RULES.md 第 7 节）。

## 根问题

小程序的后端放哪——官方 serverless、官方容器托管、自建，还是海外 BaaS？（2026-10-01 会话；用户画像：通用视角按场景分流——个人快速开发 / 团队长期维护 / 多端复用，主评微信端表现）

## 分叉与决策

### D1 微信原生集成深度要不要拉满？

- 免鉴权（openid 自动注入、免 access_token/证书管理）、微信支付/公众号一键接入（2026-05-28 集成中心）、域名白名单豁免——这些是平台特权，出了官方体系就要自己补三类合规与安全工程（见 cloudbase/cloudrun/self-hosted 报告对比节）。
- 要拉满 → D2（官方体系内二选一）
- 不要（微信只是多端之一，或团队要资产自有）→ D3

### D2 官方体系内：新建轻应用还是存量服务？

- 新建轻应用（数据 CRUD+云函数+支付）走 BaaS 一件套；存量服务/自定义运行时（Java/Go/Python 现有工程）走容器免改造迁移——「服务是新建的还是已存在的」是官方两线的事实分界（cloudrun 报告对比节）。
- 叶：[微信云开发 / CloudBase](cloudbase/) adopt（个人/快速场景默认：免鉴权+集成中心+免费 6 个月；AI 原生转型后工具链活跃）
- 叶：[微信云托管](cloudrun/) trial（存量服务官方答案：任意语言容器+callContainer 免鉴权免白名单；新建轻应用无理由绕过云开发）

### D3 面向国内还是出海？

- 用户地理决定后端地理：跨境链路是物理问题，配置优化解决不了（CloudBase 官方博客 2026-04-22 口径：Vercel 前端跨境实测 300-800ms；Supabase 无国内节点同理——见 supabase 报告）。
- 出海（海外用户为主）→ Postgres 生态+零运维的组合是正解（竞品官方博客同口径分流）。
- 叶：[Supabase](supabase/) trial（出海默认；国内小程序直连卡域名备案关，须中转层）
- 国内 → D4

### D4 国内非官方路线：资产自有优先还是 BaaS 省事优先？

- 团队长期维护/多端复用 → 资产自有压倒省事；想省运维又不想绑腾讯 → 第三方 BaaS——但现状没有健康选项。
- 叶：[自建后端](self-hosted/) adopt（团队长期/多端复用默认：代码与数据资产完全自有；ICP 备案+HTTPS+白名单三关是固定成本，运维全自担是代价）
- 叶：[LeanCloud](leancloud/) hold（公司在营但 SDK 双端冻结 3-5 年、商用版 30 元/天最低消费、无微信深集成——省事优势被云开发全面覆盖）

## 落选节点（不立条目的死分支）

- **Firebase**：国内可达性死结——Google 服务自 2014 年起被防火墙屏蔽，Firebase/FCM/Firestore 境内不可访问（AppInChina：「No, Firebase does not work in China」；Chinafy 同判）；唯一路径是京港双机 AWS 代理隧道的商业方案，等于为后端养一条跨境专线。出海产品若选 Firebase，那已是海外 App 品类的问题，不归本类别。判死证据留档 raw/2026-09-30/web/firebase-china-firebase.google.com.md。
- **Bmob（比目后端云）**：未判死、判不选——服务仍在营（服务条款页 © 2012-2026 元素（深圳）软件；hydrogen-js-sdk pushed 2026-05-27，gh 2026-10-01），但社区声量近零（2026-10-01 检索结果被无关内容淹没）、主站文档挂 old. 子域、GitHub SDK 星级三位数。与 LeanCloud 同理（专有 BaaS+无微信深集成）而存量口碑更弱，不重复立目。判活证据留档 raw/2026-10-01/web/bmob-status-tavily.json、raw/2026-10-01/gh/bmob-org-repos.json。

## 观察名单（下次复核触发器）

- uniCloud：uni-app 生态的 serverless（阿里云/支付宝云版）——后端层与前端层正交是本类别口径，但 uniCloud 是例外候选（与 uni-app 深绑）；若前端框架层选型落在 uni-app 多端复用场景，下次复核前端层时一并评估是否立目
- 云开发计费口径：2026 年内两次更迭（资源点制、AI 调用转资源点）——再变更时重算三场景成本表并复核 cloudbase verdict
- Supabase 国内直连延迟：200-800ms 均为对照/营销叙事，无 2026 年系统实测——做一次国内拨测后更新 supabase 报告（与免费档暂停策略现状一并核）
- LeanCloud：若出现 SDK 恢复维护或商业路线调整公告 → 重估 hold
- 微信云托管：拿到大促场景一手账单后，补数据库自动弹性与增值服务的实际成本弹性
