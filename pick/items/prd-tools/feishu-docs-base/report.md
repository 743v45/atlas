# 飞书文档+多维表格

> **TL;DR**：中文团队 PRD 协作的默认底座：文档写 PRD、多维表格管需求跟踪，评论/@/审批原生，AI 智能伙伴可生成 PRD 与一键搭表，Claude 经 lark-doc/lark-base 直读直写——英文生态外的最优路径。

- **结论**：adopt（推荐）
- **核实日期**：2026-08-27（自 2026-08-26 会话结论 + 官网核实）

## 为什么选

- **协作闭环开箱即用**：PRD 正文在云文档（评论、@人、版本历史），需求跟踪放多维表格（状态流转、优先级、负责人），评审走飞书审批——中文团队的协作全在同一个生态里发生，不需要为 PRD 另购工具 [5]。
- **AI 能力已进 PRD 场景**：2026-03 飞书发布企业级 Agent，自然语言描述需求即可由智能伙伴生成完整 PRD 并同步到飞书文档（量子位 2026-03-19）[3]；多维表格 AI 支持一句话搭建业务系统（官方 2025-12-26 教程）[1]；多维表格智能体可按权限回答业务数据问题（官方 2026-07-02）[4]。
- **Agent 可直读直写（本库核心命题）**：Claude 经 lark-doc / lark-base skill 直接读写文档与表格——「AI 起草 + 开发时 AI 消费」的双向工作流已被实际跑通（2026-08-26 会话实证：PRD 研究报告与模板库两篇文档由 agent 写入飞书）[5][6][7]。
- **中文原生**：界面、AI、模板、协作语境全部中文，无翻译损耗 [3][4]。

## 对比

- 与 Notion：协作能力同档，中文与本土生态是决定性差异；但 agent 批量 API 读写两者都不如裸 Markdown（见 [claude](../claude/report.md) 与 [notion-ai](../notion-ai/report.md)）。
- 与 spec-kit：飞书承载「给人读的 PRD」，spec-kit 承载「给 agent 执行的 spec」——两者是互补层而非竞争（见 `../comparison.md`）。

## 风险与注意

- **AI 按额度计费**：飞书 AI 能力有版本权益与额度消耗规则（如 PDF 智能解析每页 2 额度），重度使用需核算商业版成本（官方规则页，2026-08-27 查询）[2]。
- **数据在云端**：非本地文件，agent 自主全文检索不如裸 Markdown 顺手——PRD 若主要给 agent 当开发上下文，建议同步导出 Markdown 进 repo（2026-08-26 会话结论）[5]。
- **锁定效应**：文档与表格均在飞书云内，导出通道存在但双向同步要自己维护 [5]。
