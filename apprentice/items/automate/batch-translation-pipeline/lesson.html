批量文档翻译流水线

TL;DR:批量翻译的敌人是上下文污染与注意力衰减。一篇一文档一会话,配每篇定制的术语映射表和保持不变清单——规模化靠流水线,不靠「一次塞给它更多」。85 文件实战验证。
  • 状态:settled(定案)
  • 回答的问题:批量翻译几十上百篇文档,怎么保证术语一个口径、代码块一个不动、质量不随篇幅跑偏?
  • 验证:2026-08-24 · Claude Opus 4 系(小天机会话未核对)· claude-code

为什么整批塞一个会话不行

直觉做法是开一个会话说「把这 85 篇都翻了」——翻车三源:

  • 上下文污染:前篇的措辞选择漂进后篇,术语口径随会话推进漂移。
  • 注意力衰减:长会话到后面,「保持不变」这类约束的遵守度下滑,后翻的篇质量肉眼可见变差。
  • 错一篇重跑一批:单篇返工没有隔离边界,牵连整个会话。

流水线三件套

1. 一篇一文档一会话

每篇文档独立会话翻译:输入输出一一对应,术语污染被会话边界隔断,单篇返工只重跑该篇。批量 = 对流水线的循环,不是对单会话的加压。

2. 标准化 prompt 模板

读取:md/<slug>.md → 写出:md/<slug>.zh.md
这是什么(一句话) + 翻译要求:术语映射表(每篇定制)/保持不变:> 来源区块/代码块/API·类型名/URL/markdown 结构

模板三段:先一句话说清这篇是什么(给 AI 定基调,教程/ changelog / API 参考的译法不同),再给翻译要求,最后给不变清单。每篇只换 <slug> 和定制部分,其余零漂移。

3. 术语映射表(每篇定制)+ 保持不变清单

  • 术语映射表每篇定制,不是一套全局表走天下:开翻前先过一遍本篇的领域词,当场定死译名——「一致」的前提是先有表,而不是指望 AI 自己记得住。
  • 保持不变清单显式列出:> 来源区块、代码块、API/类型名、URL、markdown 结构。这些正是最容易「被顺手翻了」的地方,显式点名后守住。

验证

  • 保持不变核查:翻完对代码块/API 名/URL 与原文 grep 对照,一处不该动的动了 = 模板执行有漂移,该篇重跑。
  • 术语抽查:抽几篇对照术语映射表,表内词条译名一个口径;表外词条跨篇差异 → 该词条该升级进映射表。
  • 同输入对比:同一篇跑两次,输出差异应集中在表外措辞;结构性差异(小节增减、代码块变动)= 流水线不稳,先修模板再跑批量。
