# CLI for AI:给 AI 造数据访问接口

> **TL;DR**:AI 够不着的每个内部系统,都会催生一条凑合路径(人肉搬运/爬页面/curl 直怼)。别优化凑合,给数据面造正式 CLI——六次独立出现收敛成同一模式,接口持续升维:CLI → skill → 功能准入。

- **状态**:settled(定案)
- **回答的问题**:AI 访问不了内部系统,每次人工搬数据、爬页面、curl 凑合,怎么办?
- **验证**:2026-08-11 · GLM-5.2 / Claude Opus 4 系(跨双机多项目)· claude-code

## 判据:什么面值得造 CLI

不是所有接口都要造。值得造 CLI 的数据面满足两条:

- **反复访问**:文档平台、数据库、内部服务——AI 隔三差五就要读/写,不是一次性动作。
- **结构稳定**:操作面本身有清晰的动作集(查/写/改),能收敛成子命令。

一次性查询用 curl 无妨;反复访问的面还让 AI 每次现拼 curl、或人肉中转,就是在为同一个坑反复付费。

## 六现:同一模式的独立出现

| 出处 | 场景 |
|---|---|
| lucent(小天机,2026-08-11) | 用 CLI 把能力暴露给 AI,而非教 AI 更好的调用姿势 |
| subtitle-collector(小天机) | 采集数据面 CLI 化,AI 直接读写 |
| knowledge-base(小天机) | 知识库访问 CLI,AI 免爬检索 |
| 325c89be(小天机) | 内部工具会话,同一模式 |
| e3533f06(小天机) | 内部工具会话,同一模式 |
| lark-cli(本机,2026-07-29) | AI 经 CLI 全自动写飞书 wiki——用户仅两句:「lark-cli 命令行,把 robin-cli 功能全部写到 <内部 wiki 页>」「已授权。处理完在更新一下 lark-cli」,零爬页面、零人工复制,收工 |

六现的共同转折:每次的解法都不是「教 AI 更好的爬法/拼法」,而是把数据面本身 CLI 化。模式收敛到这个程度,是挣来的一刀——不是偏好,是地形。

## 升维路径:CLI → skill → 功能准入

给 AI 的接口在持续升维:

1. **CLI**:数据面有了正式命令行,AI 从「够不着」到「能操作」。
2. **skill**:把「怎么用这组 CLI 完成一类任务」沉淀成技能文件,一条命令走整套流程——AI 不用每次摸索命令组合。
3. **功能准入**:CLI 的能力边界即 AI 的权限边界——什么能读、什么能写、什么要确认,在接口层收口,而不是每次口头叮嘱。

「AI 用 curl 凑合效果不好」的完整对策在此:curl 凑合是症状,根子是缺正式接口。造了 CLI,凑合自然消失。(质量底线的表达法,见姊妹议题,不在此展开。)

## 验证

- **零交代关**:全新会话,一句自然语言让 AI 完成一次跨系统读写(本机例:两句指令写完整个 wiki 页);需要人肉搬运或爬页面才走得通 = 接口缺口还在。
- **对照**:同一动作,「AI 经 CLI」与「AI 爬页面/curl 拼接」各跑一次——成功率、耗时、出错恢复的差距,就是造 CLI 挣到的。
- **反向迭代**:用 CLI 的产出喂回 CLI 本身(本机例:「处理完在更新一下 lark-cli」)——过程中暴露的缺口当场补进接口。
