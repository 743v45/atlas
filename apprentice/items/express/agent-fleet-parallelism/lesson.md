# 并行 agent 编队作战

> **TL;DR**:任务装不进单会话时,拆成文件级隔离的子任务并发执行——每个 agent 认领不相交的文件集,每任务过 review gate,集成缝隙归主线兜底,验收轮次制。编队不是撒手,是换一种方式盯。

- **状态**:settled(定案)
- **回答的问题**:任务大到单会话装不下、串行又太慢,怎么组织多个 AI agent 并发干活?
- **验证**:2026-08-23 · GLM-5.2 / Claude Opus 4 系(跨双机)· claude-code

## 编队五纪律(按序)

1. **文件级隔离分工**:每个 agent 认领不相交的文件集——冲突在分派时就消灭,不靠事后合并。交叉处(接口、契约)先由主线定死再分派。
2. **每任务 review gate**:实现 subagent 交付后,另一个 subagent 当裁判独立验收(对照 brief 逐项核,而非重跑实现)。
3. **集成缝隙归主线**:编队只管分片交付,Makefile 漏项、模块接线这类跨片缝隙由主线会话兜底——分片交付 ≠ 系统完成。
4. **验收轮次制**:多轮验收收敛,末轮不查新问题,专「复核修复本身」——防止修复引入新伤。
5. **回传可验证证据**:agent 报完成必须带回可点开的证据(真实 URL、命令输出),不收口头「完成」。

## 实例(两机多会话)

- **robin 28-subagent SDD 编队**(07-28,本机,最完整档案):一句「能并发实现不」触发。任务先拆成带完整代码块的 brief,每任务 Implement + Review 成对;Implement 走 RED→GREEN(先复现失败测试再实现);Review 独立对照 brief 逐项核,按 Critical/Important/Minor 分级给结论。中途 subagent 被 kill,半成品由后续任务接力——**接力是常态,不是事故**。
- **holdon G1-G4 编队**(08-03):13 subagent 四组实现支付对账;Makefile 漏项由主线兜底(纪律 3 的实证)。见 [调查先行课](../audit-first-workflow/lesson.md) 的案例节。
- **11 agents 5m45s 并发写库零失败**:每个 agent 回传自己写入条目的真实 URL 自验证——把「报告完成」变成「可点开验证」(纪律 5)。
- **longxia 19-agent 三层审计**:2 句话需求启动,交付 C1-C14 编号问题清单——编号让后续修复可以逐项销号。
- **workbuddy 三路并行**:契约先行——先定接口契约,三路实现并行推进,契约即隔离面。
- **deepseek 维度切分法**:大任务按维度切片,每片附必读清单 + 穷举式指令,单会话 2-6 分钟收敛一片——切片小到「一片一坐」。
- **bili 9 路十分钟齐发**:齐发后人中途手动砍掉部分——编队允许随时裁撤,不是发出去就等。

## 验证

- 小规模试点:先 2-3 个 agent 跑文件级隔离,验收零合并冲突后再放量——第一次就全量并发是拿任务练手气。
- review gate 抽查:任取一个已过 gate 的任务,人工核 Review 报告是否逐项对照 brief(而非笼统「质量良好」)。
- 收尾必查集成面:编队全部交付后,由主线跑一次端到端(构建/启动/冒烟)——分片全绿 ≠ 系统能跑。
- 证据可点开:逐个点开 agent 回传的 URL/输出,打不开的即未完成。
