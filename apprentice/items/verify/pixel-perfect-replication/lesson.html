UI 像素级复刻验证法

TL;DR:「一模一样」不是形容词,是一张逐格核对的表。给每个元素读 computed style 的坐标/尺寸,原站与复刻各一列,格式如 24,22/104×20 ✓——全部打勾才算完。computed style 是 DOM 的客观读数,肉眼是主观印象;用前者,「像不像」变成数得清的差异数。
  • 状态:settled(定案)
  • 回答的问题:AI 复刻的页面「总觉得差一点」,怎么把像不像变成可核对的?
  • 验证:2026-08-05 · GLM-5.2 · claude-code

三句指令,逐步收敛

现场的发起方式本身就是方法:

  1. 「(目标站) 分析这个网站的 UI 设计」——先分析,不动手;
  2. 「文案用官方的。你在这里写一份。一模一样的」——「一模一样」是 Z,但它是形容词,得落地成判据;
  3. 「(预览页) 页面顶部做得不好」——AI 自认完成后,点名具体区域,而不是「再改改」。

对照 describe-the-goal 的 Z 三要素:第 2 句给了产出形态,本课补的是判据的可执行形态。

对照表:把「像」变成行和列

每个可见元素一行,读双方 computed style,并排打勾:

元素原站复刻
logo24,22/104×2024,22/104×20✓
标题140,20/320×28140,20/318×28✗ 宽差 2
按钮480,22/96×36480,24/96×36✗ y 差 2

要点:

  • 量 computed style,不量截图:级联后的最终值含继承、覆盖、@media 效果,与视觉呈现一一对应;截图量的是像素,来源不可解释;
  • ✗ 必须带差值——「宽差 2」可修,「不对」不可修;
  • 全 ✓ 是停机条件:表清空 ✗ 之前,「做完了」不成立。

多档视口:默认档全 ✓ 不算完

样式不只一套——@media 每个断点都是一套独立布局。验收要逐档跑:把窗口/仿真视口挨个过一遍,每档一张表。现场根因一(漏默认 <style> 里的 @media → 布局塌陷)正是「只验了主档」漏掉的。

验证

  • 逐格对照:坐标、尺寸、字号、颜色逐项 ✓/✗,任何一格 ✗ 即未完成;
  • 视口逐档:主样式 + 每个 @media 断点各跑一遍,各档全 ✓;
  • 点名回路:用户说「某块不好」→ 不整页重做,回表单核该区域每一格,定位到具体 ✗;
  • 字号查精确值:视觉近似值是坑,font-size 以 computed style 读数为准。
