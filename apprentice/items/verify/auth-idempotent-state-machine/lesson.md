# CLI 鉴权幂等状态机

> **TL;DR**:鉴权这种横切需求,别逐命令提要求——**用一段口语把状态机完整口述一遍**(状态、迁移、幂等、每步确认),让 AI 把它落成一个全局机制。一次讲清,处处生效。

- **状态**:settled(定案)
- **回答的问题**:CLI 的鉴权这类横切需求,怎么交给 AI 才不用每条命令重复交代?
- **验证**:2026-07-28 · GLM-5.2 · claude-code

## 口述原文:一段口语 = 一台状态机

现场原话(内部 cookie 名已脱敏):

> 「<网关>cookie 先认证的吧。认证完,就可以记录进配置,每次 auth 看看配置里的可不可用,可用就没必要再配置,除非 force 更新,如果账号已经登录,也没必要再登录,除非 logout,每一步确认鉴权通过」

这段话没有一句术语,但拆开是完整的设计:

| 口语 | 设计语义 |
|---|---|
| 先认证……认证完记录进配置 | 状态:未认证 → 已认证;凭据落盘 |
| 每次 auth 看看配置里的可不可用 | 每次使用前做**可用性检查** |
| 可用就没必要再配置,除非 force | 幂等 + `force` 迁移 |
| 已登录也没必要再登录,除非 logout | 幂等 + `logout` 迁移 |
| 每一步确认鉴权通过 | 验证织进流程,不是事后补检查 |

**为什么这比「加个登录」有效**:点需求(「加个登录」)得到的是散在各命令里的 if;一段状态机得到的是全局机制。AI 缺的从来不是写代码的能力,是完整的迁移规则——你嘴里那段「啰嗦」正是它要的规格。

## 配套五条:每条都是一句用户话催生的

同一现场,状态机之外还有五句修正,句句可复用:

1. **凭据必须先验证再落盘**——「你不验证一下吗。我随便填写的。账号密码。密码隐藏的方式输入吧……并且要验证密码」(随手粘的假 cookie 不允许拿到「已保存」的绿灯);
2. **状态码必展示**——「状态码可以展示一下.(其他的接口报错,状态码都可以展示一下」;
3. **401 关联登录提醒**——「可以提醒一下登录的。这个应该和登录接口关联的(注释一下)」:鉴权失败的报错要把「该重新登录」说出口;
4. **增删改二次确认**;
5. **不存密码存会话凭据,且落盘加盐**——「配置是不是不要保存为密码,而是登录后变成 cookie 类的」「你存在配置里是不是也得加一下 salt」。

## 验证

状态机是否真落地,按迁移逐条试,而不是看代码说有:

- **假凭据关**:粘一个乱写的 cookie → 必须当场验证失败、不落盘;
- **幂等关**:已认证状态连跑任意命令 → 不触发重新认证;重复 auth → 无副作用;
- **失效感知关**:手动改坏配置里的凭据 → 下一条命令要能发现并提示重登(可用性检查真的在跑);
- **logout 关**:登出后第一条受保护命令 → 必须要求重新认证;
- **落盘检查**:打开配置文件 → 无明文密码,凭据带盐。
